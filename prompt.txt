# Task: Create MirrorInkomik Mihon/Tachiyomi Extension

## Objective

Buat ekstensi Mihon/Tachiyomi untuk:

https://mirrorinkomik.my.id

Ikuti arsitektur repository yang sudah ada dan WAJIB mengikuti `STRUKTUR.md`.

Jangan membuat implementasi berdasarkan asumsi. Seluruh implementasi harus berasal dari hasil analisis repository dan website.

---

# Phase 1 — Repository Analysis

Sebelum menulis kode:

- Baca `STRUKTUR.md`.
- Ikuti struktur project yang ada.
- Cari minimal 3 ekstensi Indonesia yang paling mirip sebagai referensi.
- Prioritaskan referensi dari `src/id/`, helper, util, parser, filter, interceptor, dan `ParsedHttpSource`.

Jangan mengubah arsitektur project.

---

# Phase 2 — Website Analysis

Analisis seluruh website:

https://mirrorinkomik.my.id

Periksa:

- Homepage
- Latest
- Popular
- Search
- Detail
- Chapter
- Reader
- Genre/Tag
- Pagination
- HTML
- Script
- Network Request
- Ajax/API/JSON Endpoint
- Embedded Data

Cari endpoint tersembunyi jika ada.

Periksa juga:

- fetch/XHR
- REST/GraphQL
- Cookie
- Header
- Cloudflare
- CSRF/Token
- Lazy Loading

Jika tersedia endpoint yang lebih stabil daripada parsing HTML, gunakan endpoint tersebut.

---

# Phase 3 — Metadata Mapping

Pastikan seluruh metadata tersedia.

Implementasikan:

- Popular
- Latest
- Manga Detail
- Chapter List
- Reader

Ambil seluruh metadata yang tersedia tanpa menghilangkannya.

Urutkan chapter sesuai standar Mihon dan pastikan reader mengambil seluruh gambar dengan kualitas asli serta mendukung lazy image.

---

# Phase 4 — Search & Filter

Implementasikan:

- Keyword Search
- Genre Filter

Jika website memiliki advanced search atau genre dinamis, gunakan mekanisme tersebut. Jangan membuat filter yang tidak tersedia.

---

# Phase 5 — Reference Matching

Bandingkan implementasi dengan ekstensi lain yang memiliki CMS, parser, endpoint, atau template serupa.

Gunakan sebagai referensi tanpa melakukan copy-paste.

---

# Phase 6 — Code Quality

Ikuti coding style repository.

Gunakan helper, utility, parser, network client, header, dan extension function yang sudah tersedia. Gunakan `ParsedHttpSource` bila memungkinkan dan hindari membuat helper baru jika sudah ada implementasinya.

---

# Phase 7 — Validation

Pastikan seluruh fitur berfungsi:

- Popular
- Latest
- Search
- Genre Filter
- Detail
- Chapter
- Reader
- Pagination
- Metadata
- Date Parsing
- Image Request

Pastikan tidak ada parsing error, duplicate, broken image, atau runtime error.

---

# Phase 8 — Final Output

Hasil akhir harus siap di-build tanpa modifikasi tambahan.

Pastikan:

- mengikuti `STRUKTUR.md`
- konsisten dengan repository
- menggunakan endpoint paling stabil
- minim hardcode
- mudah dipelihara

Jika selama implementasi ditemukan endpoint yang lebih baik, refactor agar menggunakannya.
