# Task: Fix Login Interceptor for MirrorInkomik Extension

## Objective
Fitur utama ekstensi (parsing, search, detail, manga) sudah berjalan dengan baik. Tugas ini HANYA berfokus pada perbaikan sistem login dan interceptor agar pembaruan *session/cookie* bisa terpicu dengan benar.

## 🐛 Bug Description
Saat ini, ekstensi gagal memicu fungsi `login()` ketika *session cookie* sudah kedaluwarsa. Ketika membuka chapter, server membalas dengan HTTP 302 (Redirect) ke halaman `/login`, tetapi interceptor tidak menangkap kondisi tersebut. Akibatnya, request berlanjut dengan status *unauthorized* dan chapter gagal dimuat.

## 🛠️ Action Required
Modifikasi `loginInterceptor` di dalam file `MirrorInKomik` dengan aturan berikut:

1. **Global 302 & Redirect Catcher:**
   - Jalankan request awal ke server.
   - Periksa respons dari server. Jika `response.code == 302`, `401`, `403`, ATAU URL dari respons dialihkan ke path yang mengandung `/login`, maka sesi dianggap basi/belum login.
2. **Auto Re-login Mechanism (Jika terdeteksi belum login):**
   - WAJIB tutup respons lama (`response.close()`) untuk mencegah *memory leak*.
   - Panggil fungsi `login()` secara sinkron untuk mendapatkan *cookie session* yang baru.
   - Ulangi request asli (`chain.proceed(request)`) menggunakan *session* yang baru didapat.
3. **Pemicu Awal:**
   - Jika pengguna mengeklik halaman chapter dan status `isLoggedIn()` bernilai `false`, langsung eksekusi `login()` sebelum melakukan request pertama untuk menghemat beban jaringan.
4. **Prevent Infinite Loop:**
   - Pastikan ada logika untuk mencegah *infinite loop* jika server terus-menerus melempar respons 302 meskipun fungsi `login()` sudah dijalankan.

## 🧪 Testing & Formatting
Setelah kode dimodifikasi, jalankan perintah berikut:
- **Format:** Lakukan `./gradlew spotlessApply` untuk memastikan kode sesuai dengan standar *formatting* repository (ktlint).
- **Debug:** Lakukan pengetesan lokal. Pastikan membuka chapter yang dibatasi akan otomatis memicu log di konsol bahwa fungsi `login()` berjalan (saat respons 302 didapat), dan gambar chapter sukses dimuat tanpa *crash*.
