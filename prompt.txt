# Task: Create MirrorInkomik Mihon/Tachiyomi Extension

## Objective

Buat ekstensi Mihon/Tachiyomi baru untuk website berikut:

> https://mirrorinkomik.my.id

Ekstensi harus mengikuti arsitektur repository yang sudah ada dan WAJIB mengikuti dokumentasi yang ada di `STRUKTUR.md`.

Jangan membuat implementasi berdasarkan asumsi. Seluruh implementasi harus berasal dari hasil analisis struktur repository dan hasil scraping website.

---

# Phase 1 — Repository Analysis

Sebelum menulis kode, lakukan analisis repository terlebih dahulu.

## Wajib dilakukan

- Baca file `STRUKTUR.md`
- Ikuti seluruh struktur project yang dijelaskan di dalamnya.
- Cari minimal 3 ekstensi Indonesia yang memiliki struktur mirip.
- Gunakan implementasi mereka sebagai referensi.

Prioritaskan referensi dari:

- `src/id/`
- helper
- util
- parser
- filter
- interceptor
- extension yang memakai ParsedHttpSource

Jangan mengubah arsitektur project.

---

# Phase 2 — Website Scraping

Lakukan scraping menyeluruh terhadap website berikut:

https://mirrorinkomik.my.id

Analisis:

- Homepage
- Latest Update
- Popular
- Search
- Detail Manga
- Chapter List
- Reader
- Genre
- Tag
- Pagination
- Ajax Request
- API Endpoint
- JSON Endpoint
- Embedded Data
- Script
- Network Request
- HTML Structure

Cari endpoint tersembunyi apabila ada.

Periksa:

- fetch()
- XHR
- JSON
- GraphQL
- REST API
- WordPress Ajax
- Cookie
- Header khusus
- Cloudflare
- CSRF
- Token
- Lazy Loading

Apabila ada endpoint yang lebih stabil dibanding scraping HTML, gunakan endpoint tersebut.

# Phase 5 — Filter

Gunakan **Genre sebagai Filter**.

Jangan membuat filter lain apabila tidak benar-benar tersedia.

Filter genre harus diambil secara dinamis dari website apabila memungkinkan.

Jika website hanya menyediakan daftar tag/genre pada halaman tertentu, gunakan daftar tersebut.

Implementasikan menggunakan mekanisme filter standar Mihon.

# Phase 10 — Final Output

Hasil akhir harus berupa ekstensi yang siap di-build tanpa modifikasi tambahan.

Pastikan:

- mengikuti seluruh struktur `STRUKTUR.md`
- mengikuti coding style repository
- tidak menggunakan hardcode yang tidak perlu
- menggunakan endpoint paling stabil
- mudah dipelihara
- konsisten dengan ekstensi lain dalam repository

Jangan berhenti sebelum seluruh fitur selesai diimplementasikan.

Jika menemukan endpoint yang lebih baik di tengah proses, refactor implementasi agar menggunakan endpoint tersebut.

Prioritaskan stabilitas, performa, dan maintainability dibanding implementasi yang hanya sekadar berfungsi.
